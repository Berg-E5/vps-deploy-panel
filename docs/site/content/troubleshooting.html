Windows 本地页面打不开

  • 通过 QuickStart 启动的面板在后台运行。双击 QuickStart 可重新打开网页。
  • 打开 http://127.0.0.1:8787/api/health 检查后台版本。
  • 若提示 8787 无法绑定，请检查实际使用该端口的程序。通过 QuickStart 启动失败时可查看 .build/quickstart.stdout.log 和 .build/quickstart.stderr.log。

SSH 连接被拒绝 / 超时

从 Windows PowerShell 检查：

Test-NetConnection YOUR_VPS_IP -Port 22

连接失败说明可能是云防火墙、VPS UFW、sshd 没监听、实例停机或地址/端口错误。连接成功但认证失败，才检查用户名、密码或 SSH 私钥。如果云平台提供浏览器 SSH 入口，先从那里排查。

SSH 指纹变化、信任失败

VPS 重装、系统更新了主机密钥、IP 发生回收都可能导致指纹变化。请从服务商独立控制台核对后使用本控制台的 SSH 安全 → 更新指纹；不要使用 StrictHostKeyChecking=no 绕过身份校验。

root 密码正确但仍无法登录

需要区分 root 本地密码、SSH 是否启用密码认证、root SSH 是否被禁用，以及云平台自身的 OS Login / IAM 或 PAM 限制。修改 root 密码本身不等于开放 root SSH。

UFW 放行了，公网仍打不开

确认 VPS 真正监听对应端口、已通过有效 HTTPS / TLS 配置、云安全组的入站规则确实作用于目标实例，以及源 IP 和协议正确。云平台的 VPC 规则属于另一层网络控制。

不要用「关掉 UFW」来排连通性

那会失去本机端口过滤保护，SSH 和管理面板都暴露在外面。正确做法是精确开放所需端口，再到云安全组限制来源 IP。

计划提示失效或需要刷新

固定脚本更新后，旧审批方案会按安全规则失效。看到「此部署方案来自旧版代码」或「部署计划已过期」时，刷新页面重新生成方案即可 —— 这是防止拿旧脚本去跑新服务器环境。

安装完成但 SSH 握手失败（SSH_HANDSHAKE_FAILED）

如果日志显示安装器已返回成功，只是最后一步 SSH 连接和验收没完成，这不能证明程序没装好，请勿直接重复安装或清空原配置。

  • 更新面板并重启服务后刷新网页。新版会在执行远端命令之前最多尝试 3 次受信任的 SSH 连接，不会重复执行安装器、绕过主机指纹验证或自动重置 SSH。
  • 打开原来的失败/待验收任务，点只读检查现有安装（不重装）。它仅通过已经核对指纹的 SSH 检查服务、实际监听和本机 HTTP 响应。

需要进一步排查时，在 Ubuntu/Debian 控制台执行下面的只读检查命令：

sudo systemctl status ssh --no-pager
sudo ss -lntp | grep -E ':(22)[[:space:]]'
sudo journalctl -u ssh -n 40 --no-pager

SSH 握手失败可能与临时负载、连接限制、sshd 状态或算法协商有关，单凭这条错误无法确定根因。Test-NetConnection 成功只说明 TCP 可达，不代表 SSH 协议握手正常。

自建项目的问题

物流报价系统装完是空站 / 前台没有价格

这是预期行为：源码安装不带账号数据和报价表。登录 /admin，在后台「整表导入」上传报价表 xlsx，约 2～3 分钟生成全部价格，前台立即可用。

  • 忘记 admin 密码：在服务器上执行 node server/user.js passwd admin 重置。新装的 admin 密码随机生成并打印在部署日志里。
  • 上传后前台还是空的：后台「整表导入」面板有 7 步进度和当前步骤提示，导入失败会停在具体步骤。先看后台的改动记录页确认有没有写进去。
  • 提示端口被占：后端默认 8792，被占会自动往后挑，挑好的端口写在站点目录的 data/port 里。

音乐解锁工具打不开 / 页面空白

  • 先确认 nginx 的站点配置已生效：站点根目录应指向 /var/www/music-unlock 下的静态文件，不是后端端口。
  • 该站没有后端服务，不要去查 systemd 单元 —— 它本来就不装常驻服务。
  • 域名没解析好时可以先勾「跳过 HTTPS 证书申请」用 HTTP 验证通路。

证书签发失败 / 域名相关

  • 域名证书要求 DNS 记录已经指向这台 VPS 的公网 IP，否则签发会失败。IP 证书则要求 TCP 80 能从公网访问（做 HTTP-01 验证）。
  • Debian 13 自带 Certbot 4.0 不支持 IP 证书。本控制台在 IP 模式下会自动建独立 Python venv、装 Certbot 5.8.0 并配 vpsdeploy-certbot-renew.timer，不卸载系统旧 Certbot。看到 Installed Certbot does not support IP certificates 时更新面板后重试证书步骤即可。
  • 证书失败时不会退化成公网明文：服务会保持或恢复本机监听，用 SSH 隧道访问，并可单独重试证书阶段，不用覆盖重装。

其它项目的常见问题

其它内置项目的安装步骤与验收方式见 部署指南。几个通用的高频问题：

  • 装完了但只显示本机地址：走部署向导里的「开启公网 HTTP」审批任务改监听即可，不用重装、也不用重新申请证书。
  • 反向代理之后打不开：容器在普通桥接网络下，127.0.0.1 指向容器自己，反代不到宿主机。要把对应的 Compose 服务改成 network_mode: host 并删掉原来的 ports: 映射后重建容器；代价是 80/443 等端口变成宿主机端口，必须限制管理端口的访问来源。
  • 高权限项目首次打不开或被抢先注册：这类项目挂载 Docker Socket、权限很高，新装默认走公网 IP + 端口。先在云安全组把来源限制为自己的管理 IP，或用 SSH 隧道完成初始化。
  • 管理页只监听本机：用 ssh -N -p 22 -L <本地端口>:127.0.0.1:<远端端口> root@YOUR_VPS_IP 开隧道访问，不要直接开放公网。

如何反馈故障

在 GitHub Issues 留下：面板版本、VPS 系统、CPU、执行项目、出错阶段和脱敏的最后一步错误。禁止上传私钥、密码、令牌或真实服务器地址。
