安装计划不等于已经在你的 VPS 上验证成功

本控制台 v{{version}} 仍是 Alpha；自动安装已通过本地模拟测试，但不同 VPS 镜像、上游网络和防火墙仍可能产生差异。先用测试服务器。

自建项目：物流报价系统 · 音乐解锁工具

这两个项目由本控制台作者自己维护，源码在公开仓库里，排在项目库最前面。部署流程和通用项目完全一致：固定 commit 下载 → 校验 install.sh 的 SHA-256 → 装环境 → 执行安装 → 验收。端口被占或目标项目已安装时会直接阻断，不会覆盖。

物流报价系统

多用户物流报价计算与改价后台。部署目标是 Berg-E5/logistics-quote 的固定 commit。

  1. 在项目库选择 物流报价系统，填站点域名（必填），可填安装目录（留空用默认 /var/www/quote.byberg.store）。DNS 还没配好时可以勾「跳过 HTTPS 证书申请」先用 HTTP 验证。
  2. 安装会创建 quote-server systemd 单元、写 nginx 站点配置，并在 8792 起后端（端口被占会自动往后挑，挑好的端口写在 data/port）。首次启动生成随机 admin 密码并打印在部署日志里。
  3. 装完是空站：源码安装不带账号数据和报价表。登录 /admin 后在后台「整表导入」上传报价表 xlsx，约 2～3 分钟生成全部价格，前台立即可用。忘记密码用 node server/user.js passwd admin 重置。
  4. 多用户隔离：每个账号看到的是自己上传的报价表，admin 改的价格不会串到别的账号。
想要「装完就有数据」

走带数据的发布包安装（仓库里的 deploy/install-remote.sh），那条路会带上现有账号和费率。走 GitHub 源码安装则一定是空站，需要自己上传报价表。

音乐解锁工具

浏览器端加密音乐本地解锁。部署目标是 Berg-E5/music-unlock 的固定 commit。

  1. 在项目库选择 音乐解锁工具，填站点域名（必填），安装目录默认 /var/www/music-unlock。
  2. 纯静态站：服务器只放静态文件和 nginx 配置，没有后端、没有数据库、不装常驻服务。解密在浏览器 Worker 里跑，文件不上传服务器。

部署是怎么执行的

添加 VPS → 核对指纹 → 环境检测 → 可选网络配置 → 生成方案 → 审批执行。

面板不会「点一下就不经确认地运行远程命令」。它先检查系统版本、端口占用和已有安装，再生成一份可逐行查看的固定脚本；你确认之后才会在服务器上执行。执行过程和每一步的输出都记录在任务记录里。

方案在审批前会再跑一次环境检测。如果服务器状态在这期间变了 —— 比如端口被别人占了、目标程序已经装好了 —— 面板会拒绝执行并要求重新生成方案。

安全底线

  • 每个项目钉在具体 commit，不追 main 分支 —— 主分支随时会变，不能直接执行。
  • 下载后落盘再校验 install.sh 的 SHA-256，不匹配立刻中止；不做 curl | bash 管道。
  • 执行的是仓库里已审阅的 install.sh，不是远程一键脚本。
  • 端口被占、目标项目已装过 → 直接阻断，不覆盖。
  • nginx 会 enable + restart 并确认在运行；验收会真的 curl 打自己的 vhost（带 Host 头），只看 nginx -t 不算数。

上游项目的几个要点

各项目的端口、证书与安装参数由部署表单在生成方案时逐条列出，安装前可以逐行审阅，这里不重复抄写会随版本变化的细节。只记容易踩的坑和补救动作。

3X-UI / S-UI

  • 已装的面板优先点 查看已安装面板，不要直接重装。旧安装若只显示本机地址，点「开启公网 HTTP（不申请证书）」审批两步监听变更任务即可，无需重装、无需重新申请证书。
  • 证书失败时面板不会退化成公网明文：S-UI 会保持或恢复 127.0.0.1:2095，用 SSH 隧道访问，点继续完成 HTTPS单独重试证书阶段。订阅 2096/TCP 永远只监听本机。
  • Debian 13 的 IP 证书：系统自带 Certbot 4.0 不支持 IP 证书。本控制台在 IP 模式下会自动建独立 Python venv、装 Certbot 5.8.0 并配 vpsdeploy-certbot-renew.timer，不卸载系统旧 Certbot。曾在「步骤 7/9」失败的，更新面板后点继续完成 HTTPS，只重试证书步骤。
  • NPM 统一 HTTPS：该模式不调用 Certbot、不占 ACME TCP 80，只做 5 步基础安装。NPM 的 Forward Host 填 127.0.0.1（3X-UI 端口可改、S-UI 为 2095），3X-UI 要开 WebSockets Support。
NPM 的 Docker 网络模式

普通桥接网络里的 NPM 容器，127.0.0.1 指向容器自己，不能直接反代宿主机。要用这些上游地址，需把 NPM 的 Compose 服务设成 network_mode: host，并删掉原来的 ports: 映射后重建容器。代价是 NPM 的 80/443/81 会成为宿主机端口，必须在云安全组限制 81 管理入口。

Dockge Apps

  • 管理端口留空时自动随机生成 20000–59999，也可手填 1024–65535，会检查与 SSH 和现有服务的冲突。
  • 全新 Debian/Ubuntu 没有 Docker 时会自动执行 Docker 官方一键安装脚本，验收 Compose v2、Buildx 与 Git 后继续。脚本先做语法检查、dry-run 和文件校验再执行本地副本。
  • 安装后点查看 Dockge Apps 面板信息；已有受管理的实例可用修改端口与访问方式，只改容器端口映射并保留数据，不重装。
默认公网直连的安全注意事项

Dockge Apps 挂载 Docker Socket，有很高的 VPS 管理权限。新安装默认走公网 IP + 端口，审批时会再次提醒：首次管理员还没创建时，能访问该端口的人可能抢先注册。建议先在云安全组限制来源为自己的固定管理 IP，或用 SSH 隧道完成初始化。Docker 映射端口可能绕过 UFW；本控制台不会自行修改云安全组。

sing-box / wg-easy

sing-box 只安装内核，不会自动产生可用节点、TLS 证书或公网监听，需自行完成合法配置并运行 sing-box check。wg-easy 默认隧道用 51820/UDP，Web 管理页绑定 127.0.0.1:51821，首次访问用 SSH 隧道初始化：

ssh -N -p 22 -L 51821:127.0.0.1:51821 root@YOUR_VPS_IP

失败、重试与日志

任务列表会显示等待审批、执行中、已完成、部分成功或失败状态。出现异常时，先看最后一步的实际日志，再通过服务器控制台核对远端程序状态。不同版本的固定脚本变更后应刷新旧审批方案，不能继续执行过期计划。
