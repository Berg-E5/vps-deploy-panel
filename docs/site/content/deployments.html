安装计划不等于已经在你的 VPS 上验证成功

本控制台 v{{version}} 仍是 Alpha；自动安装已通过本地模拟测试，但不同 VPS 镜像、上游网络和防火墙仍可能产生差异。先用测试服务器。

自建项目：物流报价系统 · 音乐解锁工具

这两个项目由本控制台作者自己维护，源码在公开仓库里，排在项目库最前面。部署流程和通用项目完全一致：固定 commit 下载 → 校验 install.sh 的 SHA-256 → 装环境 → 执行安装 → 验收。端口被占或目标项目已安装时会直接阻断，不会覆盖。

物流报价系统

多用户物流报价计算与改价后台。部署目标是 Berg-E5/logistics-quote 的固定 commit。

  1. 在项目库选择 物流报价系统，填站点域名（必填），可填安装目录（留空用默认 /var/www/quote.byberg.store）。DNS 还没配好时可以勾「跳过 HTTPS 证书申请」先用 HTTP 验证。
  2. 安装会创建 quote-server systemd 单元、写 nginx 站点配置，并在 8792 起后端（端口被占会自动往后挑，挑好的端口写在 data/port）。首次启动生成随机 admin 密码并打印在部署日志里。
  3. 装完是空站：源码安装不带账号数据和报价表。登录 /admin 后在后台「整表导入」上传报价表 xlsx，约 2～3 分钟生成全部价格，前台立即可用。忘记密码用 node server/user.js passwd admin 重置。
  4. 多用户隔离：每个账号看到的是自己上传的报价表，admin 改的价格不会串到别的账号。
想要「装完就有数据」

走带数据的发布包安装（仓库里的 deploy/install-remote.sh），那条路会带上现有账号和费率。走 GitHub 源码安装则一定是空站，需要自己上传报价表。

音乐解锁工具

浏览器端加密音乐本地解锁。部署目标是 Berg-E5/music-unlock 的固定 commit。

  1. 在项目库选择 音乐解锁工具，填站点域名（必填），安装目录默认 /var/www/music-unlock。
  2. 纯静态站：服务器只放静态文件和 nginx 配置，没有后端、没有数据库、不装常驻服务。解密在浏览器 Worker 里跑，文件不上传服务器。

部署是怎么执行的

添加 VPS → 核对指纹 → 环境检测 → 可选网络配置 → 生成方案 → 审批执行。

面板不会「点一下就不经确认地运行远程命令」。它先检查系统版本、端口占用和已有安装，再生成一份可逐行查看的固定脚本；你确认之后才会在服务器上执行。执行过程和每一步的输出都记录在任务记录里。

方案在审批前会再跑一次环境检测。如果服务器状态在这期间变了 —— 比如端口被别人占了、目标程序已经装好了 —— 面板会拒绝执行并要求重新生成方案。

安全底线

  • 每个项目钉在具体 commit，不追 main 分支 —— 主分支随时会变，不能直接执行。
  • 下载后落盘再校验 install.sh 的 SHA-256，不匹配立刻中止；不做 curl | bash 管道。
  • 执行的是仓库里已审阅的 install.sh，不是远程一键脚本。
  • 端口被占、目标项目已装过 → 直接阻断，不覆盖。
  • nginx 会 enable + restart 并确认在运行；验收会真的 curl 打自己的 vhost（带 Host 头），只看 nginx -t 不算数。

其它项目怎么装

项目库里还收录了若干通用开源项目（代理面板、代理内核、Docker 应用中心等）。它们各自的端口、证书方式、镜像来源和前置条件都不一样，而且会随版本变化 —— 以面板里该项目的安装说明为准，生成方案时会逐条列出这一单实际要执行的步骤与参数。

通用规则只有一条：每个项目都钉在具体 commit，下载后校验 install.sh 的 SHA-256，端口被占或已装过就直接阻断，不会覆盖你现有的东西。审批前会再跑一次环境检测，服务器状态变了会要求重新生成方案。

失败、重试与日志

任务列表会显示等待审批、执行中、已完成、部分成功或失败状态。出现异常时，先看最后一步的实际日志，再通过服务器控制台核对远端程序状态。不同版本的固定脚本变更后应刷新旧审批方案，不能继续执行过期计划。
