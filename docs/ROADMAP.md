# 开发阶段与验收清单

这份文档说明当前版本做到了什么、还差什么，以及每一项的验收标准。
待办按主题分组，不按版本号排。

## 当前版本 v1.0.0（Alpha）

已具备：

- [x] 跑在本机的单管理员 Web 界面，默认只监听 `127.0.0.1`
- [x] 服务器记录管理，SSH 主机指纹需人工对照后手动信任
- [x] 远程环境检测：系统版本、架构、root 身份、磁盘余量、Docker、端口占用
- [x] 项目目录驱动，安装步骤固定到具体 commit 并校验 SHA-256
- [x] 两阶段审批：先生成可逐行查看的方案，确认后才执行
- [x] 任务状态、步骤级日志与日志脱敏
- [x] UFW 端口批量放行，以及云厂商安全组配置页快捷入口
- [x] 3X-UI / S-UI 的 IP 证书与域名证书流程
- [x] 只读诊断接口（只给建议，不代跑命令）
- [x] 自动化测试：恶意主机输入、脚本篡改阻断、失效方案拒绝执行

## 真实验收

面板的每条路径都需要在真实环境上跑通才算数。以下项目都需要一台**可以重置的 VPS**：

- [ ] 3X-UI 安装、失败中断与恢复演练
- [ ] 完整走通第一个成功流程（安装 → 证书 → 公网 HTTPS 访问）
- [ ] 证书、密码已变更、面板端口已更改等异常场景的恢复
- [ ] APT 锁处理、证书签发、续期与公网端口连通的实机验收
- [ ] Ubuntu 26.10 上复测 3X-UI CLI 设置持久化、系统服务监听与公网访问
- [ ] Let's Encrypt 公网证书签发、短期证书续期与公网连通性，并模拟失败回退
- [ ] 云安全组 TCP 80 开放后的实际 Certbot IP 证书签发与续期
- [ ] 实机验证端口实际状态与云厂商入站安全组
- [ ] S-UI 全流程：归档内容、系统服务、密码与本地 HTTP 验收
- [ ] 3X-UI TLS 证书配置与事务回滚，以及多系统实机验证
- [ ] 域名 HTTPS 在真实 VPS 与多种分辨率下的实测
- [ ] Codex Worker 在真实登录环境的端到端验收

## AI 辅助

AI 在面板里只做只读诊断与建议，任何会改动服务器的动作仍走审批。

- [ ] 统一的远程只读检查接口，变更仍需单独审批
- [ ] AI 根据失败日志提出备选修复方案，先审批再调用固定修复动作
- [ ] 可恢复任务队列（Redis / Postgres / Worker）与状态对账

## 规模化与运维

- [ ] CI 增加虚拟机集成测试矩阵：Debian / Ubuntu × x86_64 / arm64
- [ ] 经真实 VPS 与多系统测试的全自动部署矩阵
- [ ] 安全审计、供应链签名、操作回放与定期更新策略
- [ ] 稳定部署包、发布渠道、升级迁移与安全披露机制

## 发布门槛

一次发布要满足下面全部条件：

- 全量自动化测试通过
- 相关路径在真实 VPS 上验收过
- 文档与实际行为一致
- 变更在 CHANGELOG 里写明，并标注是否需要重新生成部署方案
